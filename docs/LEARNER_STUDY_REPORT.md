# Learner study improvements

The operator requested all three suggested additions and asked for a minimal dashboard with only important information. The implementation provides:

- Completed-attempt review controls for all, incorrect, unanswered, correct and flagged answers, with combined subject/text filters, live result counts, original question numbers and focus-preserving reset. Full answer text and stored explanations remain visible. Filters never write responses, change a grade or store private content in URLs/localStorage.
- An account-home dashboard with one main next action, three compact recent-progress figures, one course-progress bar, the latest result and one subject recommendation. Secondary account/security/staff/order tools are in a collapsed native disclosure. Marketing announcements and the header promotion are hidden on this page. Existing authenticated history/series summaries remain the only data sources; no new private-question endpoint or migration is introduced.
- Six additional original public draft teaching chapters, one in each reviewer guide, with twelve worked examples and six short practice exercises/rationales. The displayed library total becomes 29 learning chapters: 23 original lessons plus six supplements. Contents, public metadata search and browser printing include the additions. New Markdown files use a fixed server-side allowlist and cannot load assessment packs or arbitrary paths.

The dashboard prioritizes accessible active attempts, then the next available course step. Suggestions use recent subject ratios and fixed public guide links. Missing data displays an unavailable value rather than invented progress. Paid-access, ownership, deadline, source-version, unreviewed-practice and commercial-release gates remain unchanged. No questions are published or given synthetic reviews, no account emails are sent and no payments or registration are enabled.

Validation: lint, TypeScript, 127 unit tests, content validation and the production build passed; tracing found 52 valid manifests and 916 runtime files, including the six added public Markdown files. The full browser suite passed all 39 checks on desktop/mobile, including new dashboard and result-filter workflows, real browser printing, ownership isolation, partial-data retry and empty-state/reset behavior. The four signed-in accessibility workflows and two timed-mock browser workflows also passed. After the final minimalist layout adjustments, all ten focused account/dashboard/result/reviewer browser checks and all four sequential-set workflows passed. The final production build again verified all 52 manifests and 916 runtime files. Desktop and mobile dashboard screenshots were also inspected. Automated scans are not manual accessibility certification or independent content review.
