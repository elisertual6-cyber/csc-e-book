# Optional reviewer bookmarks

Learners can choose **Bookmark chapter** at the start of any of the 29 public reviewer chapters, including all six extra-practice chapters. One bookmark is retained per guide. Saving another chapter in the same guide replaces its previous bookmark; pressing a saved chapter's button again removes it. The Reviewers library and legacy `/shop` library show **Continue reading**, with the most recently saved guide first. Each guide's sidebar shows its own saved chapter. Links open the exact chapter anchor; the browser handles scrolling. No reading activity is inferred or automatically saved.

This is an explicitly chosen **browser-only** convenience, available without signing in. It does not synchronize with accounts or other devices. Bookmarks are shared by anyone using the same browser profile, persist through sign-out, and disappear if browser site data is cleared. The visible notice explains that scope and advises against saving on shared devices. **Clear all reviewer bookmarks** removes only this feature's key, leaving planner settings and other storage alone. The learner dashboard remains unchanged and minimal.

The single versioned localStorage entry `csc-study:reviewer-bookmarks:v1` contains only a version and up to six public guide/chapter identifiers. No timestamps, reading history, identity, grades, question text, answers, tokens or credentials are stored. Destinations and labels are reconstructed from the fixed public reviewer and supplement catalogs. Malformed/oversized records, duplicate guides, extra fields, unknown or mismatched chapters and arbitrary URLs are rejected. Corrupt records can be cleared or replaced by an explicit bookmark action; merely visiting a page never writes storage. This is separate from the account-owned exam service and cannot mark lessons or sets complete, change grades or unlock later sets.

Client controls use `useSyncExternalStore` with a stable server snapshot to preserve prerendered public guide content and hydration. Same-tab changes and other-tab storage events update all visible controls. Mutations read the current storage value before modifying it rather than relying on an old render. Browser storage still uses last-write-wins semantics if two tabs change it simultaneously; it is not a transactional or durable account store. Read/write failures report unavailable saving without marking a bookmark as successfully saved. Reading, contents navigation and browser printing remain available. Buttons expose their pressed state, keyboard focus remains on the bookmark button, and clearing returns focus to the still-visible section heading. Bookmark controls/notices are omitted from printed guides.

No API, database table, migration, environment setting, mail, content review/release or commerce change is introduced. Public Markdown stays on the server and the bookmark code imports only public metadata. Existing draft labels, assessment secrecy and paid-PDF gates remain in force.

Validation uses pure parser/allowlist tests and the existing isolated browser wrapper. Desktop/mobile coverage checks opt-in persistence, replacement/removal, returning to an exact anchor, cross-tab synchronization, corrupt data recovery, read/write storage failures, preservation of unrelated settings, print visibility, responsive layout and automated accessibility. Automated scans do not establish manual conformance.
