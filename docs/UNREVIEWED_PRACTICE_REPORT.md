# Operator-authorized activation of five unreviewed practice sets

The operator explicitly requested all five 160-question sets activated without their review. This release implements that request as labelled FREE unreviewed practice, preserving the actual DRAFT editorial states and review history. It does not manufacture independent approvals, release PDF editions or relax ordinary topic/mock/commercial review checks.

A current ADMIN can run `practice:activate-unreviewed -- --apply`. The operation locks the five fixed templates and validates all 800 complete latest question versions before activation. Missing, malformed or archived questions prevent all five from being activated. Authorizations contain the exact question IDs, keys, versions and content hashes in existing private AuditEvent records; no migration is needed. Repeating an unchanged release creates no duplicate authorizations or template version increments. Changed question content is blocked from new attempts until explicitly authorized again; existing attempt snapshots retain their original content.

Attempt creation accepts the explicitly authorized non-archived draft versions only within these five FREE untimed templates. Correctness flags and explanations remain private until complete submission. Set cards and active/completed attempts show that the questions and proposed keys are unreviewed. All 160 answers are still required before submission, no passing score is required, and predecessor completion remains server-owned and account-bound.

The new main-only Activate five sets as unreviewed practice workflow runs on pushes changing `content/releases/five-practice-sets.json`, and supports manual reruns. This release-intent file records the user's explicit instruction. It uses the existing database/admin secrets and database-operation concurrency group, checks the already applied schema, and activates the already imported sets. Hosted import run [40447939468](https://github.com/elisertual6-cyber/csc-e-book/actions/runs/40447939468) was observed successful through the public workflow page. No repeated import is necessary.
