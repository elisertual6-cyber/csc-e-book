# Focused mistake-practice delivery

Added a learner-controlled retry action to completed or expired results. The learner can select incorrect questions, unanswered items or both. The server creates a fresh untimed attempt from the exact authorized source snapshot, keeps original results unchanged, returns fresh public question identifiers and withholds the new key/explanations until grading. Current paid-access checks remain enforced on creation, replay and all later reads/writes. No source Question/Review states, template releases, schema, environment settings or commercial gates change.

The new endpoint has strict input and mutation validation, owner checks, shared start rate limits, the existing three-active-session cap, per-user start serialization and request-hash idempotency. Browser retries preserve the start key after an unknown response. Existing source mode/access/draft status is represented truthfully, and retries use the normal history/dashboard resume flow without adding dashboard clutter.

Fixed-course queries now require the matching immutable series marker. Full-size retry attempts keep separate retry metadata without a series marker, so they cannot count toward course completion, appear as an active course set, replace a full-set start or unlock later sets. A synthetic 160-item completed retry verifies that boundary.

Validation: lint, TypeScript, 127 unit tests, content validation and the production build passed (53 verified trace manifests, 917 runtime files). The six dedicated desktop/mobile retry checks passed, covering all selection modes, a lost start response, persistence, pre-grade privacy, fresh identifiers, frozen source versions, original-result immutability, perfect-result behavior, owner isolation, expired-source cleanup, strict input, start-key collisions, concurrent starts/quotas and premium revocation. Four sequential-series checks and all 39 general browser checks passed. Local database integration passed. All four authenticated accessibility workflows and both timed-mock workflows also passed on desktop/mobile.

A first parallel run hit an existing serializable conflict while creating synthetic editorial fixtures, before any retry operation. The dedicated suite now runs fixture creation sequentially, while explicitly testing concurrent retry requests within its cases. No real editorial content was approved or changed. Tests use generated disposable databases; automated accessibility results do not establish manual conformance or independent content review. Hosted deployment is verified separately from these local checks.
