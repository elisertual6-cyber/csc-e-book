# Focused practice for missed questions

After a session is submitted or expires, its result offers **Practise what you missed**. Choose incorrect and unanswered questions together, incorrect selections only, or unanswered items only, then start focused practice. A perfect result shows a short message instead of an empty-session button. The dashboard stays minimal; retries use the existing saved-session/history flow.

Each retry is a separate untimed PRACTICE attempt with fresh opaque question IDs, no copied answers/flags and its own score. It uses the exact private question versions and proposed keys from the authorized saved result. Later bank edits or template deactivation do not replace those saved versions. This is historical practice, not a new editorial publication or an assertion that a previous draft has been corrected. Unreviewed notices are inherited from the source. The previous result remains unchanged; an earlier-result link lets learners return to it. Answers and explanations are withheld again until the new attempt is graded, though the learner can still view their already completed earlier result.

`POST /api/exams/attempts/:id/retry` accepts only `{startKey, selection}` with a UUID and `missed|incorrect|unanswered`. The server recomputes membership from saved responses and the immutable private snapshot. Counts, keys, answers, score, timer and access overrides are rejected. Source ownership, current PREMIUM access, Origin/action headers, private/no-store responses, shared exam-start rate limiting and the three-active-session cap apply. The source must be finalized; overdue attempts are finalized through the existing database-clock cleanup. A per-user advisory lock and request hash serialize creation and bind a start key to its exact source/selection. Retrying an unconfirmed request uses the same key; another selection needs a new key. The same start key cannot be reused for an ordinary exam request.

No schema migration, bank import, template activation or environment change is required. The retry retains its source template foreign key for access/history continuity, but its immutable metadata has a separate `retry` marker and deliberately omits `series`. Fixed-course completion, active/resume queries and full-set deduplication explicitly require matching series metadata. Even a submitted 160-question retry cannot count as a course completion or unlock the next set. Existing attempts without retry metadata remain valid.

No learner state or keys go into localStorage, query parameters or new exports. Current purchase/access checks continue at retry creation, replay, read, save and submission. No question statuses or human Review records are changed. A retry of a retry uses that retry's missed items while keeping the base title short; it is still separate practice.

Use `npm run test:exam-retry` and `npm run test:practice-series` through their disposable wrappers. Retry fixtures run sequentially because editorial creation performs global serializable duplicate-prompt checks; concurrent retry starts are explicitly exercised inside the test. Coverage includes browser persistence, a lost start response, idempotency, wrong/blank selections, hidden pre-submission keys, fresh question IDs, frozen old versions, no source-result mutation, perfect results, owner isolation, current premium revocation, shared quotas and full-sized retries excluded from sequential progress. All fixtures are synthetic and never approve or activate real content.
