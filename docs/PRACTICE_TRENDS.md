# Recent practice result trends

Practice history now includes **Recent result trend**, a chart and compact first/latest/change figures for up to ten completed sessions. The native **Compare sessions** selector can narrow the view to sessions sharing a title, track, mode and question count. The default shows all recent completed sessions, including focused retries. Those groups can still contain different question versions, selections and difficulty; the interface describes a comparison of practice percentages, never exam readiness or a passing prediction. Change means the percentage-point difference between the first and latest displayed percentages, not a relative percentage improvement or an average.

The view uses only the existing authenticated `/api/exams/history` summary, which includes all active attempts and the latest 50 finalized attempts. Active, missing, invalid and impossible grades are excluded from chart points. Group filtering occurs before taking the latest ten matching entries. The server-provided newest-finalized order is reversed for oldest-to-newest presentation; start dates are deliberately not used to reorder resumed sessions. No dates are invented as completion timestamps. Matching entries beyond the API's recent-50 window are unavailable, not silently fetched or represented as lifetime totals. Expired, graded sessions are included and labelled in the details table. A single result has a point but no fabricated change; an empty history has a prompt rather than a zero-score chart. Failed or loading history never shows synthetic trend data.

The SVG has a text alternative listing its percentages in order. A keyboard-accessible native disclosure opens the same numbered results as a table, with exact correct/total values, track/mode/status and existing owned-result links. Locked premium summaries remain visible, but receive no explanation links; attempt APIs continue to enforce current access. Filters are client-memory presentation state only and change neither the saved history list, results, five-set unlocks nor the minimal account dashboard. No questions, answers, scores or settings are persisted to browser storage or query strings. There are no extra API reads, schema/migration changes, environment settings or assessment releases.

Pure tests cover empty/single/expired histories, invalid denominators/grades, the ten-result window, ordering, immutable inputs, exact group boundaries and positive/negative/unchanged percentage-point differences. Desktop/mobile browser tests use real synthetic authentication and explicitly stubbed summary data to exercise filtering, links, locked access presentation, keyboard focus, chart/table parity, empty/single/failure states, layout and automated accessibility. These UI fixtures are not real learner grades or new backend authorization evidence. Existing authenticated exam/security tests cover the unchanged history service. All browser suites must run through the disposable-database wrapper; automated scans are not manual accessibility conformance.
